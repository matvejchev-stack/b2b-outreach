# Проверка комплекта и его версии

Читай при подготовке повторяемых комплектов, замене файлов и точном
согласовании письма. `scripts/check_package.py` — необязательный локальный
помощник на Python 3.9+, без сетевого доступа, установки библиотек и отправки.

## Подготовка

Скопируй [пример manifest](../assets/package.example.json) в папку конкретного
комплекта. Это заготовка с вымышленными адресами; без настоящих файлов,
дат и контрольных сумм она не проходит проверку. Не заполняй её наугад.

- Укажи кампанию, устойчивый ID комплекта, реальный аккаунт и одного To.
  Скрипт принимает обычный адрес без отображаемого имени: ASCII до `@`,
  домен может быть международным. Проверка синтаксиса не доказывает
  существование и назначение ящика.
- Свяжи ID адресата, страну и язык с карточкой кандидата.
- Укажи тип `first_contact`, `reply`, `follow_up` или `referral`.
  Для ответа и напоминания сохрани также `thread_id` исходной переписки.
- Сохрани точное тело письма в UTF-8 файле и посчитай его SHA-256.
- Перечисли ожидаемые виды вложений и все фактические файлы с SHA-256,
  адресатом, языком, а для официального письма и датой документа.
  Если вложения не нужны, оба списка оставь пустыми. Пример с двумя PDF
  не устанавливает такой состав для всех кампаний.

Пути относительны папке manifest. Другие каталоги и ссылки за её пределы
отклоняются. Хеш тела вычисляй по окончательным байтам; не нормализуй переносы
после проверки. Для HTML сохрани фактически отправляемое тело, отдельно
проверь текстовую альтернативу и оформление используемого транспорта.

## Запуск

Из папки установленного навыка, подставив путь к своему manifest и фактическую
локальную дату планируемой отправки:

```bash
python3 scripts/check_package.py /path/to/package/manifest.json --account sender@example.invalid --send-date 2026-11-17
```

После смысловой/визуальной проверки сохрани выданный `package_sha256`
в журнал проверки или точного согласования, если такое согласование требуется.
Перед транспортом запусти ту же команду с `--expected-digest` и сохранённым
отпечатком. Не пересчитывай его молча вместо сравнения.

Код возврата `0` и `integrity_checked` означают совпадение файлов с manifest,
проверку отправителя, одного To, отсутствия Cc/Bcc, состава вложений,
указанного языка, ID адресата и заявленной даты официального письма.
`reviewed_digest_matched: true` дополнительно подтверждает совпадение отпечатка.
Ошибка возвращает код `1` и `hold`. Используй фактически проверенные файлы
без изменений и повторно проверь вложения в отправленном сообщении.

Помощник сверяет метаданные с файлами по хешам, **не читает смысл PDF**
и не подтверждает правильность внесённых имени, телефона, языка или даты
внутри документа. Он не проверяет историю, полномочия, квоту, доставку
и не блокирует параллельных отправителей. Эти проверки остаются в
[operations.md](operations.md); результат скрипта не даёт разрешения отправлять.
